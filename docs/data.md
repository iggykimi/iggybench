# Raw data

The raw measurements are attached to the `v1.0` release as `iggybench-raw-v1.tar.gz`, with its SHA-256 next to it.
Unpack it into `raw/` at the repository root (the analysis scripts look there, or wherever `IGGY_RAW` points).

## Layout

```
iggybench-raw-v1/
├── README.md                this page
├── runs_index.csv           tag, run folder, batch
├── results/<tag>/<run>/     one folder per model battery; <run> is the server's local start time (UTC+8)
│   ├── runs.csv             one row per measured point, with its start and end time (epoch seconds)
│   ├── json/                `vllm bench serve` result per point; per-request TTFT, ITL and lengths where kept
│   ├── gpu.csv              nvidia-smi every second: power (GPU and module), utilisation, memory, temperature, clocks
│   ├── vllm_metrics.csv     vLLM queue, KV-cache use, prefix-cache hits and speculative acceptance every 2 s
│   ├── metrics/             full /metrics snapshots before and after each test block
│   ├── logs/                client log per point
│   ├── server_cmd.txt       the exact server command line
│   ├── server_models.json   /v1/models at start
│   ├── suite_info.txt       tests, image, SLOs and settings of the battery
│   └── <task>.json          task-test results (agents, sessions, reasoning, BFCL, e-mails, invoices, ...)
├── logs/                    queue logs and per-battery logs, one folder per batch (batch2, queue4, queue5-9)
├── env/                     vLLM collect_env output, nvidia-smi, and each model's config.json
└── derived/                 tables computed on the server before the batch-2 detail was deleted
    ├── batch2_point_stats.csv     per-point statistics of batch 2 (same code as analysis/point_stats.py)
    └── <batch>_resumen_runs.csv   server-side summary per point, including vLLM counters
```

The task-test file names (`agentes.json`, `dificil.json`, `sesiones_fino.json`, ...) and their JSON keys are in
Spanish, as the scripts wrote them at the time. [`bench/SCHEMA_GLOSSARY.md`](../bench/SCHEMA_GLOSSARY.md) maps every
file, key and value to English, and the end of [runs.md](runs.md) lists the frozen labels used in test and profile
names (`agentes`, `estandar`, `@rafagas`, ...).

## What is and is not in it

- Batch 1 and the last two queues are complete, with per-request detail and telemetry.
- Batch 2 kept only aggregate results per point: the per-request arrays and the GPU telemetry were deleted on
  the server to save disk after the per-point statistics were computed. Those statistics are in
  `derived/batch2_point_stats.csv`, and `analysis/point_stats.py` uses them for batch-2 points.
- Removed before release: the generated text of every serving request (random-token or ShareGPT prompts produce
  output of no use and of unclear licence), the server's host name and user name, the GPU's serial number and UUID,
  the list of other container images on the host, a nested archive of the scripts, and the runs discarded after
  the DeepSeek crash described in [lessons-learned.md](lessons-learned.md). Paths under the user's home directory
  were rewritten to `/home/user`.
- Kept: failed and partial runs that are part of the record (for example the first speech attempt with the stock
  image, and a T4 sweep marked `T4-descartado` in batch 1), the predictions and references of the quality tests, and
  the full server logs.

## Third-party data

No dataset is redistributed except as model inputs and outputs inside result files: GSM8K (MIT), MATH-500, AIME
2025 and 2026, BFCL v3 (Apache 2.0) and FLEURS (CC BY 4.0). `bench/prepare_data.sh` downloads them from their
sources. The invoices and e-mails are synthetic and generated by the scripts in `bench/`.
